How to read these layouts (hover ⓘ next to a layout name for its own explanation; full text: docs/INTERPRETING.md)
  • Colour. Node and intra-layer edge colour = layer. Cross-layer edges in the report renders are red; in movie frames they fade from one layer's colour to the other's. Black (report) / white (movies) nodes = the focus set (e.g. seeds).
  • Nodes are copies. With an entity column, one entity (e.g. a gene) has one node per layer it occurs in. Aligned layouts put its copies at matching positions; free layouts let each copy follow its own layer's network.
  • Closeness. In force-directed and neighbour-embedding layouts, nodes that are close are well connected (or share neighbourhoods). Local neighbourhoods are reliable (see nbr_recall); large distances between far-apart clusters are much less so, especially for t-SNE / UMAP.
  • Orientation. Rotation and mirror image are arbitrary unless an axis is given a meaning (z = layer in stacks, radius = score in score layouts, ...). Compare shapes, not directions.
  • Size of a cluster. Area / spread is not a reliable size measure in t-SNE / UMAP-like layouts (they equalise densities); use counts instead.
  • Metrics. nbr_recall: share of a node's graph neighbours among its nearest points (local faithfulness). trust / shepard / stress: global faithfulness. layer_sil: how separated the layers are. ent_dist_rel: how well copies of one entity line up (lower = more aligned). func_coherence: do nodes sharing annotation terms sit together (1 = random). occlusion: how much nodes hide each other in the best 2D view. score: median percentile over the ranked metrics; pareto: not beaten on every metric by another layout.
